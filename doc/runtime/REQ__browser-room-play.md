# Actual browser room play

Browser room play uses the actual prepared game competition identity and the
portable room client through BrowserRoomOwner/WebTransportChannel. Native and
browser transports adapt the shared protocol; remote reported progress never
becomes the local audio or judge clock. A direct room protocol fixture with
constructed score words does not establish actual gameplay.

The creator seals a collecting roster only after at least two hosts join.
Every admitted host marks Ready before one committed start is delivered to each
host. Actual local audio preparation and output observations gate activation.
Original chart, seed, section, input mode and selected judging policy must agree;
incompatible identity cannot enter Ready or play. Forbidden Origin and untrusted
TLS destinations must fail actual admission without a fabricated start.

During play, real keyboard input reaches local judging and captured recording;
the other host receives that local game's reported score prefix. Natural
completion requires each original local result/record proof, local final write,
final acknowledgement and genuine coordinated drain. A terminal label or one
completed host does not prove complete two-host play. Leave/abort preserves the
original cancellation/prefix distinction and joins owned transport/audio/input.

Acceptance uses current production Main/Workers/AudioWorklet and generated WASM,
real Play clicks and independently focused hosts. Preserve blur/visibility stop
behavior; use isolated browser processes/displays instead of suppressing events.
Record raw host IDs, starts, gameplay/remote scores, terminal fields, errors,
screenshots and joined cleanup. Inspect the visible roster, Playing and Results.

## Verification boundary

Strict trusted acceptance uses ordinary Chromium certificate verification:
no certificate-ignore, SPKI-ignore, forced QUIC or WebTransport developer flags,
no injected transport factory, fingerprint trust or synthetic gameplay.
Disposable user NSS trust can establish HTTPS while Chromium QUIC still rejects
an unknown system root. Verify actual stream acquisition separately before
running the protocol/gameplay fixtures. An unavailable system-trusted endpoint
leaves acceptance BLOCKED_ENV; source presence and local bypass probes cannot
complete WBS12.04. Native/browser interoperability remains part of that WBS leaf.

Physical audio synchronization, cross-OS devices, ranked authority and complete
player performance remain separate requirements. Setup and evidence instructions
live in [the verification guide](../verification/GUIDE__browser-room-acceptance.md).
