# Audio scheduling and native Windows output implementation

The core now preloads bounded finite interleaved PCM from supported WAV forms,
retains samples in an owned bank, and delivers scalar commands through a
fixed-capacity safe atomic SPSC queue. A preallocated mixer places commands on
one absolute frame grid, preserves same-frame submission order and exact sample
phase across callback partitions, and supports overlapping voices, signed/zero
rates, Seek and explicit capacity/error counters. Its render and queue paths
have independent allocator tests for allocation, reallocation and deallocation.
The [core contract](../kernel/REQ__audio.md) defines the timing and ownership
boundaries.

The platform implements native WASAPI device/probe boundaries and worker-owned
shared and exclusive streams. Callers explicitly select format, device, period,
buffer, supported-rounding policy, wake policy and MMCSS priority. Shared
IAudioClient3 selects an engine period; legacy shared event uses native default
buffering, while explicit shared timer mode exposes adjustable buffer duration.
Exclusive event mode uses matching buffer/period with advisory alignment and
opt-in retry. Applied sizes remain separate from the original request.
Allocation-free conversion packs valid-bit PCM16/24/32 or finite Float32 into
native buffers; raw numeric COM calls keep fill failures outside projected
error ownership. Stop wakes and joins before owned assets are released.
Clock snapshots retain native position/frequency and the 100 ns QPC association
mapped through the caller's existing clock origin. The
[Windows contract](../platform/REQ__windows-audio.md) specifies these APIs.
Native reading quality is reported separately from mapping uncertainty, which
remains unknown without a measured error bound. Portable unit tests exercise
the actual fixed telemetry publisher/reader and running deadline observations,
including concurrent publication, generation exhaustion, terminal status
visibility and exclusion of Ready-state delay from deadline accounting.

On Rust 1.98.1, coordinator checks pass 178 tests including doctests in each of
debug and release on Linux, formatting, documentation, Linux strict Clippy,
Windows platform strict Clippy and Windows all-target compilation. Rebuilt
examples pass 120 independent CLI boundary checks on Linux. Additional mixer
tests cover allocation-free rate changes, atomic multi-voice rejection,
44.1-to-48 kHz stereo resampling and bounded queue admission across partitions.
Independent review identified and prompted fixes for reserved speaker-mask bits
accepted by the public API and downward period clamping under an upward-only
rounding policy. Regression tests cover both public construction and native
format parsing, plus frame/duration limits under both negotiation policies.
Further review prompted fixes so failed Start acknowledgments join before
returning, native size errors retain queried constraints, unchecked exclusive
size suggestions are omitted, and only running clock observations contribute
to deadline intervals. Windows-owned-thread unit tests cover the acknowledgment
cleanup branch and panic reporting; these tests were compiled but not executed
in the available Linux environment and do not attest actual COM failure handling.
Successful native output and final Phase 7 acceptance remain pending. Windows-only
tests and ignored native playback fixtures are not established by Linux tests.

## Known ceiling

A live sample head's rate change rejects an exact common denominator that
cannot fit signed 128-bit arithmetic, preserving the previous rate and all
heads. Successful native shared/exclusive output is still unverified; previous
native enumeration in the retained Windows VM returned zero render endpoints.
The current Linux environment lacks a Windows GNU linker, so newly linked native
test binaries are not yet available. Inferred starvation/deadline metrics are
not authoritative hardware underrun counts, and no physical latency benchmark
has been measured. ASIO requires a resolved licensing/distribution path and is
currently explicitly unresolved. Linux/macOS native audio, integrated gameplay,
projection, replay, generalization, parsers, conditional FFI and optimization
remain required later phases of the original plan.
