# Selected native live judgment classes and EX score

Explicitly selected native BMS policies now flow through the shared cold
gameplay bridge into the Player's per-member scalar snapshots and live HUD,
independently of recording. Linux, Windows WASAPI/optional ASIO and macOS
launchers pass the same selected policy. The renderer receives EX, PG, G, GOOD,
BAD and POOR counters; unclassified builtin play retains its existing display.
Classified local panels reserve 24 pixels and shift comparison/playfield bounds
together. Unknown classes, overflow, mismatched capture identities and invalid
runtime/roster setup refuse before publication or device/control effects.

Focused verification: ten genuine Runtime/Player/admission fixtures and three
HUD geometry/scalar fixtures pass with `desktop,webtransport`. Fixture lifecycle
checks use actual published snapshots and establish a real runtime frontier
before fencing. Full regression and independent review/GUI QA remain pending;
this document does not claim task or full-player completion.

## Known ceiling

Native CLI selection still uses the existing simple PGREAT window and missed
stage POOR policy. Full historical judgment windows and empty POOR are not
implemented by this change. Browser play and custom network policies retain
their current selection limits. Rust cross-target checks do not prove physical
audio/input, SDK compatibility or performance. World-leading latency and
SQLite-grade stability remain goals requiring separate evidence.
