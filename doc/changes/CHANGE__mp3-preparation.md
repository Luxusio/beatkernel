# MP3 assets and declared encoder timing

Shared default preparation now dispatches initial ID3/MPEG signatures to app-only MPEG1/2/2.5 Layer III decoding. Complete fixed-source-format frames, CBR/VBR bitrate changes and frame padding are validated before owned PCM allocation. The decoder keeps reservoir/synthesis state and uses fixed frame scratch; skips, partial frames, codec failures, format transitions and output over the caller cap fail setup. Protected frame CRC16 validates header and side information. Float PCM preserves source rate and mono/stereo channels; existing channel expansion and sample-bank limits remain in force.

Default TaggedGapless skips the first Xing/Info metadata frame, checks declared following audio-frame counts and applies supported LAME/Lavc timing: leading encoder delay plus 529 decoder frames and trailing padding minus 529. Insufficient declared padding or cuts beyond actual decoded frames reject. Missing timing metadata retains raw decoded frames without guessing a delay. Explicit RawFrames keeps all following decoded audio frames while still validating the metadata/frame stream. Delay/padding cuts happen before bank admission, preserving the common native/offline/live/replay clock mapping and original chart identity.

Missing literal references can resolve through 36 unique WAV/FLAC/OGG/MP3 extension-case combinations. Original supported extension families retain priority and mp3's digit does not create duplicate candidates. Literal/candidate errors never fall through, custom codec lookup remains Exact, and original Unicode references are unchanged. Authored fixtures cover MPEG versions/channels, protected CRC, source errors, metadata/trim/raw policy and bounds. Actual shared preparation compares a tagged synthetic MP3 with728 retained source frames against literal WAV, captured replay setup identity and actual offline Runtime/Mixer PCM alongside a nonzero WAV head. Post-expansion caps, suffix-independent content dispatch and damaged-literal refusal are also prepared. Fixtures are compiled only, never executed.

Pinned nanomp3/nanomp3-core 0.2.0 are application-only dependencies with scalar Layer III features and no C build. Exact published MIT notices are retained. Core and BMS adapter dependencies remain unchanged.

## Known ceiling

Free-format, Layers I/II, ID3v2.2, APEv2, unknown nonzero Xing encoder extensions and clipped streams requiring unavailable reservoir are unsupported. One initial ID3v2.3/v2.4 and final ID3v1 are bounded/skipped; metadata contents are not parsed. Xing audio-frame counts and LAME/Lavc delay/padding are checked; encoder/tag checksums and optional byte-count/seek fields are not. CRC16 does not protect all compressed main data. Source rate/channel transitions reject. Untagged encoder latency is unknown; no absolute acoustic synchronization claim follows from raw MP3 decoding. Scalar codec/frame scratch is separate from caller retained-output limits; encoded input is at most64MiB, but no processing-time or whole-process memory bound is claimed. Unwinds become preparation errors without changing hooks; allocation/process aborts and panic-abort builds cannot be recovered. Filename containment assumes trusted static directories. Exhaustive codec, tests, native device/GUI/WASM and performance acceptance remain pending.
