# Ogg/Vorbis through actual preparation

Shared default preparation now dispatches OggS content to app-only Rust Vorbis decoding before playback. Complete single logical streams retain source rate/channels and produce finite interleaved f32 without an intermediate integer quantization step. Strict page framing, CRC, serial/sequence/BOS/EOS/continuation and granule checks precede codec work; declared final frames and cumulative owned PCM obey caller limits. App-owned final-packet trimming uses cumulative decoded frames even when all audio shares one EOS page; page granules are checked only at page completion. Missing EOS, corrupt/truncated/trailing input, chains/multiplexing, unsupported Ogg codecs and frame-count mismatches fail preparation. Codec unwinds become preparation errors in unwind builds; global panic hooks are unchanged. Existing channel expansion, bank limits, native clocks, judging and original-time replay are unchanged.

Missing literal assets can resolve through 32 ordered WAV/FLAC/OGG extension-case combinations. The supported original family comes first, then remaining WAV, FLAC, OGG families; exact Unicode stems/directories are retained. Existing literal/candidate errors still fail immediately, and the existing custom-codec API stays Exact. Original BMS references remain unchanged. Actual preparation fixtures use an original synthetic mono Vorbis asset with all audio on one EOS page under a mixed-case Unicode OGG filename referenced as WAV, check 48 decoded frames and stereo expansion, combine it with a nonzero WAV head through actual offline Runtime/Mixer, and prepare damaged-literal and storage-limit cases. Decoder/container fixtures are authored and compiled only; no execution result is claimed.

Pinned lewton 0.10.2 adds ogg 0.8.0, tinyvec 1.13.3 and byteorder 1.5.0. Ogg is an explicit application container-reader dependency at the same pinned version. Exact published license texts are retained in application third-party notices; authored code remains MIT. Core and BMS adapter dependencies are unchanged.

## Known ceiling

The supported input is complete zero-origin single-stream Ogg/Vorbis. MP3, other Ogg codecs, chained/multiplexed streams, nonzero-origin timing and exhaustive Vorbis conformance remain unfinished. The 64 MiB encoded and caller decoded-output caps do not bound codec setup/comment/scratch allocation or total CPU work; this is not an isolated CPU/RAM sandbox, and allocation/process aborts or panic-abort builds cannot be recovered. The standard sole identification packet on BOS is required. Source channels must fit the existing 1–32-channel AudioFormat, with no implicit multichannel layout/downmix. Filename lookup assumes trusted static directories and is not race-free containment. Tests, native endpoint/GUI/WASM execution and performance acceptance remain deferred; compilation alone proves no runtime behavior.
