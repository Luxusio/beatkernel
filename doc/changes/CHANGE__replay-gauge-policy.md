# Replay gauge setup identity

Stepped solo/local capture and comparison setup now retain each nondefault
resolved gauge profile in a canonical application options wrapper. Default
profiles preserve previous options bytes. Bounded decoding rejects malformed,
nested and redundant default wrappers; legacy tuple consumers refuse policy
metadata they cannot retain. Replay setup validation regenerates the complete
header before use. Incremental replay and audio planning observe the recorded
policy, including judgment depletion in charts without mines. Catalog policy
comparisons include the resolved gauge. Core replay envelopes and judge hashes
are unchanged. Focused fixtures cover byte compatibility, exact budgets,
truncation/corruption and actual capture, reconstruction, visual gauge and audio
sound stops. Independent code, security and documentation review passed.
Independent QA ran the final runtime library (1,598 passed, 0 failed, 2 ignored)
and application main (242 passed, 0 failed), including the real capture/visual/
audio tests and solo/local completion header-policy assertions. Workspace
all-targets, browser WASM and normal Windows/macOS all-targets source checks
each reached terminal exit 0. Cross checks use C stubs and establish source
compatibility, not native SDK bridge, HAL, GUI or physical audio execution.
The latest CLI help exited 0; an invalid mode exited 1 with the expected
application-mode error. Nondefault policy has no public CLI selector yet;
its behavior was tested through actual library entry points.

The native replay publication bridge still admits default profiles only; its
connection to validated recorded policies remains unfinished. This does not
expose gauge selection in native/browser launchers or claim full
LR2 mine/empty compatibility. Actual driver/audio delivery, public configuration,
and the full player acceptance remain unfinished.
