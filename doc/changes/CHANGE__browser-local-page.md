# Browser local player page integration

The page connects explicit local source assignment to the existing shared
Worker gameplay owner. Solo stays automatic. Two or more players select distinct
acquired sources after discovery, retaining real HID/Gamepad owners and their
source/sequence identities through session adoption. Player IDs survive roster
resizing; retired IDs are not reused. Freeze the plan before asynchronous audio
preparation and validate the returned roster, page and capture budgets.

Window filters unassigned keyboard, touch, HID and Gamepad input before queueing
the original samples. Worker owns bindings, judging, scores and four-field paged
rendering. A selected touch player starts on its own visible field; page changes
remain subject to the Worker's current contact-layout restriction.

Discovery has a synchronous operation identity. Cancellation, overlapping
discovery, disconnect, focus loss and host reset cannot adopt stale asynchronous
results. Cleanup releases acquired devices/listeners; failed cleanup fences
further play until reload. Device names are labels, not ownership identities.

The page validates individual capture receipts, retains readable siblings after
one export failure, and offers explicit member selection for download or library
save. Final score and recording ownership stay per member. Local network and
saved-opponent combinations refuse before acquiring audio; existing solo and
recorded playback use their established paths.

The 64-member roster is independent of the 256-binding-row budget and browser
acquisition limits of 16 HID interfaces, 16 Gamepads and two aggregate sources.
Unavailable sources and incomplete chart coverage refuse setup. Separate physical
keyboards are not exposed by the browser keyboard aggregate.

Verification remains deferred: fixtures are authored for helper admission,
actual page ownership/filtering, metadata refusal, cancellation and independent
capture selection. No JavaScript parser, test, browser, device, audio, generated
binding, build/link, formal review or QA execution is claimed. The full player
Goal remains open, including per-member saved/network comparisons, contact page
remapping and runtime/performance acceptance.
