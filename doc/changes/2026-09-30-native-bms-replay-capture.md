# Native BMS accepted-operation capture

The separate BMS runtime can record the actual live Runtime's accepted input
prefixes and successful explicit advances through the existing core replay log.
Windows, Linux and macOS roots offer an optional new output path and explicit
operation/encoded-byte caps. Reports preserve unoffset song times and physical
provenance, including operations whose audio admission failed. Capture errors
stop the session and leave a valid prior prefix; encoding and exclusive file
creation happen after native cleanup attempts. Header identity binds the pristine
compiled judge/profile setup with a noncryptographic hash. The core remains
BMS-independent, and its durable replay format is unchanged.

## Known ceiling

Finite caps can stop long sessions unless increased. Encoded-byte caps do not
bound total process memory; temporary codec work and retained logical records
allocate on the control thread. Source files, PCM and physical audio timing are
not recorded or authenticated. Fixture and native execution, independent reviews
and QA remain deferred; cross-target cargo check only establishes buildability.
