# macOS graphical local play

Settings Players now supports the same 2..64 stable member roster on macOS.
Typed keyboard catalogs assign exact positive IORegistry identities; numeric
aliases fail atomically. Profiles and explicit overrides replace the whole solo
registry/local-player family. Group defaults skip solo keyboard discovery.

The native composition polls one IOHID owner and feeds original normalized Mach
metadata into the existing bounded InputMerger and RuntimeGroup. One CoreAudio
output, PCM bank, BGM scheduler and transport accompany independent member
judges, scores, ghosts, replay captures and completion. Native attachment loss,
queue loss, chronology failure or partial runtime failure stops the cohort.
Committed report prefixes survive; output stop and HID close precede attempts
to save every per-member .p<ID>.bkr recording with create-new semantics.

Count64 is a roster ceiling, not an acceptance claim for any device workload.
Voices remain1..4096, acquisition/merger queues65536, bounded256-record drains,
advance lag0..1s (default2ms), and backlog freezes the common deadline frontier.
Exact device IDs are refreshed per session, separate from persistent player IDs.
Combined local groups and network mode reject before resources. Keyboard button
capability alone does not certify HID keyboard class. Physical timing is unknown.

Source checks and fixture authoring may proceed. Actual tests, device discovery,
GUI/GPU/native audio/input, files/network and formal review/security/QA/close
remain deferred at the user's request. Full player work, including expanded
practice/transport controls and browser native adapters, remains active.
