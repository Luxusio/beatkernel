# Retained record class scores

Record preparation retains separate checked class/EX summaries for reconstructed
prefixes and associated stored historical results. Retained record preview and
detail geometry consume those scalar values, include them in cache identity and
show unavailable for unclassified or missing score data. Repeated identical
frames reuse geometry and existing shared score storage. Invalid summary math or
counter relationships refuse before changing retained state. Header decoding and
class projection remain in preparation, not per-frame rendering. Prefix labels
sit left of page buttons; stored values occupy the detail right column, while
generic left-column score text clips within its own bounds.

Verification: the rebuilt original workspace passed 2,715 tests, zero failures
and six ignored across 118 targets; the runtime library passed 1,652 with two
ignored and explicit desktop/WebTransport binary suites passed 367. WASM/browser
source check passed. Independent code, security, CLI, desktop and browser lenses
passed this bounded record-view scope. Actual X11 at 960x720 displayed prefix EX2
and stored EX8 separately, missing/legacy unavailable markers, navigation and
unchanged repeated geometry. The rebuilt shipped browser host displayed stored
EX8/PGREAT4/POOR1 and missing/legacy markers under Vulkan SwiftShader; page refusal
and return-to-preview preserved the expected lifecycle. Logs/screenshots are
local ignored artifacts under `target/wf/record-score-ui-qa-*`.

Verification harnesses that copy a workspace package to expose test-only helpers
must use an isolated `CARGO_TARGET_DIR`. Reusing the product target directory can
mix identically named runtime/core artifacts; compilation diagnostics may point
to the copied package even when the real dependency graph contains one version.
Keep failure logs, clean only affected local package artifacts and rebuild the
original workspace before accepting the result.

## Known ceiling

These are reconstructed-prefix and historical archive views, not live completion
evidence. Live host/HUD class-policy propagation, historical combo/window rules,
native physical and full browser execution acceptance remain work under the full
Goal. ANGLE-only software WebGPU reproducibly loses its graphics device during
chart preparation (`A valid external Instance reference no longer exists`).
Vulkan SwiftShader passed the scoped host flow; the other backend failure remains
unresolved and is not attributed to the class-score change. Preserve the browser
failure logs instead of treating successful verification on one backend as
universal graphics acceptance.
