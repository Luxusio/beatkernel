# Shared local member preparation

Linux, Windows and macOS local sessions use one preparation owner for admitted player/device assignments, exact bindings, independent judges and keysound voice allocation, replay capture, saved opponents and full/finite completion metadata. Shared activation constructs the runtime group and input merger with the same actual calibrated origin. Sparse player identities and native attachment IDs remain intact.

Native code still owns device selection, stream negotiation/calibration and output-before-input cleanup. After cleanup attempts, common finalization finishes every opponent and attempts every unambiguous recording save even after another failure. Destinations match player IDs rather than positional zip. Session, cleanup and save failures are all retained, including on Linux. Solo and cohort paths share the existing create-new capture writer.

## Known ceiling

Native asset/mixer and remaining stream/resource composition are still platform-owned. ASIO interval-aware committed startup remains unfinished. Actual device timing, acoustic restart synchronization, file publication, desktop and network acceptance remain deferred. Authored fixtures and compile checks do not prove those properties.

All five compile-only configurations passed: Linux workspace/all targets,
Windows GNU application/all targets, macOS application/all targets, headless
application/all targets and the WASM graphics library. The first native checks
found a test-only `Rate` import error; after every process stopped, that import
was corrected and all four affected configurations passed. Final dedicated
`target/ac146-{host,windows,macos,headless}-2.exit` and
`target/ac146-wasm.exit` artifacts contain zero. Scoped formatting/diff checks
passed. Existing macOS `block` future-compatibility and WASM cadence warnings
remain.

Six source-only fixture groups cover sparse 2/3/4/64-player rosters, exact
bindings, disjoint voice namespaces, real runtime input and replay capture,
section/epoch/admission errors, and reordered or ambiguous recording
destinations with continued saves after failures. These fixtures were compiled
without execution; no native, filesystem, socket or desktop acceptance is
inferred.
