# Browser live saved-record competition

AC-200 connects the existing saved-opponent bindings to the browser Window and
Worker host. Selection uses actual local stored records and imported replay
Files, with an explicit Own/Other display classification. Both kinds are
unauthenticated metadata. Native/browser gameplay, recording and replay continue
to use the common runtime and replay judge.

The page retains at most eight immutable Files with a 64 MiB aggregate budget.
Add, individual removal and Clear govern that selection; refusal preserves the
previous entries. Repeated selection of the same source is refused. Bounded
plain labels may shorten a filename for display without altering the file.
Local storage load uses the existing operation owner and cancellation stamp.
Files remain reusable for retry and are not detached by Play. Preparing a live
session resumes audio within the original gesture, then sends descriptors to
its Worker. Replay playback ignores this comparison selection.

The Worker validates declared membership and sizes, reads files sequentially,
checks each actual byte extent and owner after the await, and invokes the real
BrowserGame admission before activation. An incompatible or malformed selected
record fails preparation explicitly. Stale reads cannot add to a stopped or
newer gameplay owner. The prepared response reports genuine admitted count.

During live play the Worker requests genuine saved-prefix snapshots at most
four times per second. Actual game song time drives the common Rust comparison;
the display throttle is not a clock source for judging. Counter fields remain
BigInt, the last recorded operation stays explicit, and truncated or empty
recordings never gain invented misses. The Window accepts only the current live
owner's bounded snapshot and writes text to a separate comparison readout.
Comparison failure fences that publication alone, preserving local gameplay,
audio, capture completion and optional live multiplayer. Peer-reported network
scores remain separate. Chart and recording bytes are not sent to the relay.

Independent JavaScript fixtures are authored for real host boundaries and the
selection component. Binding instrumentation tests routing and lifecycle; it
does not replace the Rust replay-judge evidence. JavaScript parsing, assertions,
product/browser/audio execution, generated bindings, formal review and QA remain
deferred. Rust sources are unchanged in this milestone, so previous compilation
is not relabelled as JavaScript verification. Goal active, task open/PENDING.
