# Linux local input composition

Linux terminal play accepts 2..64 ordered, explicit `--local-input PATH` values for one shared song/output and independent player judgments, scores, completion and replay captures. Solo defaults remain automatic in the primary app. A bounded input merger preserves acquisition metadata and orders all devices before advancing common deadlines; backlog suppresses advancement and input older than a committed deadline fails explicitly. Repeated device groups survive settings profiles/overrides. Character-device aliases are rejected from opened descriptors. Multiple-player GUI presentation and Windows/macOS acquisition remain unfinished; Linux groups explicitly reject GUI and two-peer network mode. Source compilation is separate from executed gameplay acceptance, which remains user-deferred.

## Known ceiling

Local rosters are bounded to64 players and each merge queue to65536 events/64MiB retained storage. Native kernel scheduling can deliver input later than the configured lag; this causes an explicit failure and cannot establish physically drift-free playback. The current Linux composition shares one chart/lane binding scheme across devices; differing per-player charts/bindings and GUI roster setup remain future work. The 256-record per-device acquisition batch does not advance deadlines when any node remains backlogged. Existing two-peer network competition still represents one local participant per peer. Runtime tests, native/device/UI/audio/file/network execution and independent review/QA remain deferred.
