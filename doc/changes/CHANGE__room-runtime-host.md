# Room runtime host injection

The room controller receives startup/final waiting controls and implicit-drop
diagnostics through a generic `RoomRuntimeHost`. Native runtime construction
preserves existing constructors and checked fixed deadlines, while injected
controls permit the same controller lifecycle to be exercised without native
sleep or clocks. The controller still uses genuine observed schedules, final
receipts and joined outcomes; control injection supplies no completion authority.

## Known ceiling

The controller's concrete defaults and native start-agreement compatibility
remain native. Worker IO, full portable controller construction, result
presentation separation and actual platform/performance acceptance remain work.
Six independent controller fixture groups are authored but unexecuted. After
both writers stopped, scoped formatting and four sequential compile-only checks
completed with exit zero: workspace/all-targets with WebTransport,
no-default-features WebTransport/all-targets, WASM browser/library and WASM
browser-audio/library. Remaining warnings concern existing unused code. The
WASM checks compile the portable host contract, not the native controller or its
fixture child. Scripted receipts do not prove real ACK delivery or native timing
and joins. Test execution, formal review and QA remain deferred.
