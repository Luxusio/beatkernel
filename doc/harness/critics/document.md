# Document critic playbook

- Require durable docs to match code, tests, and observable behavior.
- Preserve the full requirements in `plan.md` and distinguish completed phases from pending work.
- Make requirements discoverable from the project summary and README.
- Check public API descriptions, commands, licensing, and platform support against actual files.
- Avoid claiming hardware support or verification that has not run.

PASS when changed durable knowledge is accurate, discoverable, and consistent.
