# Bounded BMS parser/compiler corpus

The BMS adapter is exercised by a finite, reproducible corpus without adding a
fuzzing dependency or replacing parser/compiler failures with caught panics.
The corpus uses fixed xorshift seeds and bounded loops. It is ordinary authored
Rust test code; its creation and compilation do not claim that it has run.

Valid generated documents combine explicit base BPM, indexed BPM, STOP,
fractional measure length, instant notes, layered BGM and paired LNTYPE1 holds.
Independent piecewise song-time expectations check pre-STOP endpoints and
post-STOP timing. Adding zero subdivision slots, changing line endings and
adding descriptive metadata must preserve compiled gameplay/BGM timing. These
checks compare semantic results, not a golden value generated by the compiler.

The text corpus has 256 byte cases and 256 mutations, with at most 512 raw bytes
per arbitrary case and bounded mutations of valid documents. UTF-8 conversion
is an explicit adapter boundary: invalid raw byte strings are not submitted as
unchecked text. Their lossy text counterparts are also parsed. Every parser
call uses limits of 4096 input bytes, 128 lines, 256 bytes per line, 64 combined
source items and 4096 ticks per beat. Successful results must respect these
output bounds and pass through the actual core compiler; compile failures must
retain the document-wide line-zero error shape. Parse errors must identify a
bounded source line or explicit document-wide failure. Fixed adversarial cases
assert typed limit, missing-definition, unsupported, long-note and arithmetic
failures with independently selected expectations.

A separate 128-case structured core SourceChart corpus varies BPM, STOP,
subdivision resolution and hold endpoints. Piecewise rational arithmetic in the
fixture independently predicts timestamps. Permuting source order and scaling
all beat ticks/resolution together preserve compiled objects. Boundary cases
exercise representable high-resolution/extreme tick inputs, timestamp overflow,
STOP addition overflow, duplicate markers and reversed ranges. Counts and
metadata sizes are bounded before compilation.

Tests are authored but must remain unexecuted while the user's verification
deferral applies. Scoped rustfmt and cargo check of the test target are allowed;
no execution, performance result, review or QA verdict is implied by compilation.
