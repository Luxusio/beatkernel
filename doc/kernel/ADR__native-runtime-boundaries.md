# Native runtime boundaries

The user requires native capabilities to be abstracted as far as their actual semantics allow. Gameplay, replay/judgment, multiplayer protocol, screen lifecycle and playback scheduling policy belong in shared runtime code. Operating-system modules provide device ownership/operations, normalized clocks, native acquisition and required cleanup. An OS entry point must not contain an independent multiplayer implementation or repeat the playback-start state machine. Native evidence and limitations remain explicit; abstraction must preserve clock domains, native reading quality, bounded intervals, provenance, callback constraints and failure semantics. Unsupported capabilities are reported rather than replaced with invented observations. No additional crates are required merely to establish these boundaries.

The first migration makes native_start::start_committed the single owner of silent-device startup, bounded calibration, early agreement, session/host bracketing, observed-slope physical-frame projection, exact arming, actual presentation crossing and cancellation/deadline policy. NativeStartDevice exposes only start, bounded acquisition service, normalized observation with original evidence, actual render report/buffer extent and native host sampling. NativeStartAgreement adapts the existing shared LiveCompetition protocol; fake adapters exercise the same owner using an actual gated mixer. ALSA/CoreAudio provide normalized pairs; WASAPI retains its exact accepted snapshot and physical native origin. ASIO requires a bounded-interval adapter before claiming equivalent frame startup.

This migration does not claim all platform code is already thin. Solo and local-cohort gameplay now each have a shared owner; setup/discovery and some resource/recording glue still reside in native entry points. Continue moving shared decisions and sequencing into common components, leaving the unavoidable native calls and resource ownership behind adapters. Preserve bottom-up component construction, one application crate, retained UI and deterministic shared judging/replay. Compiling native adapters is not physical runtime acceptance.

Future presentation coordinates are native capability semantics that the shared owner must handle uniformly. Retain the first qualifying crossing evidence and service acquisition/status/BGM until actual normalized native host time reaches its playback origin. Keep the same deadline and cancellation handling; host-domain/regression errors reject. Do not publish readiness or shift the saved crossing merely because native metadata describes a buffer's future presentation.

Performance remains part of the boundary. Use generic device traits/static dispatch for shared owner paths where practical, reserve startup acquisition storage before use, and keep device waits, clock sampling, locks and allocation out of the audio callback. Abstraction does not imply per-note signals or per-event object allocation. Error boxing on the control owner does not move policy or allocation into real-time rendering.

The second migration places the complete solo gameplay pump in native_gameplay::run_gameplay. NativeGameplayDevice retains only native observation, host sampling, bounded acquisition, end evidence and observation-source reseeding. Shared code owns pause/resume/input admission/watermark/judgment/capture/competition/completion sequencing. The parsed advance lag applies across platforms, and native source identity survives resume. Native setup/discovery remain subsequent migration work; local-cohort loops use the shared owner described below.

The local-cohort migration uses native_cohort::run_cohort over the existing RuntimeGroup and InputMerger. It reuses NativeGameplayDevice, preserving native buffer/end/clock capabilities. Windows solo and cohort sessions use the same Raw Input/output adapter, with a selected attachment slice and original WASAPI snapshot reseeding. Linux adapters retain fair bounded sweeps across evdev owners; macOS retains IOHID health and exact attachment checks. Shared policy owns admission during pending acknowledgements, deterministic merged ordering, one lag frontier, pause-prefix commits, release reconciliation, partial-report capture and actual all-member completion. Per-player configuration, activation and replay saving now use the common composition described below. Asset loading and native cleanup operations remain explicit composition boundaries; audio construction is shared as described below.

Default preparation now has one owner in native_defaults::prepare for both live play and replay watching. It plans required metadata queries after strict application syntax validation and preserves explicit options. auto_native supplies OS default identity, actual output format, keyboard candidates and explicitly requested ASIO replay format operations. Keyboard selection policy and metadata admission bounds are shared; the adapter preserves native IDs and ordering evidence. The SettingsHost branches describe option-schema/capability differences without duplicating preparation sequencing in OS entry points. Native stream setup and ASIO interval-aware committed startup remain subsequent work; local member construction is shared as described below.

Local member composition now belongs to native_cohort_setup: one admitted roster creates exact-device bindings, isolated judges and sound voices, captures, record opponents and full/finite completion metadata. The same owner activates RuntimeGroup and InputMerger from the actual calibrated origin. Native adapters still resolve attachments and negotiate/own streams. After their output stop/join and input close attempts, common finalization matches recording destinations by PlayerId, finishes every opponent and attempts every unambiguous save while preserving session/cleanup/save failures. The create-new capture helper is shared by solo and cohort callers. Native asset loading, calibration and remaining resource composition are subsequent work; this migration does not establish ASIO interval startup or physical acceptance.

Native audio construction now has one owner in native_audio::prepare_audio. It derives the exact bank format, maps section BGM to the declared output/preroll grid, reserves1024 command slots for live work and creates the existing finite/gated mixer. Each native caller supplies its actual rendering bound: ALSA period, CoreAudio buffer or the Windows callback hard bound. Supported solo network modes select initial gating; local sessions and the current ASIO path remain ungated. native_audio::feed_rendered owns checked logical-playback cursor replenishment for both startup and gameplay, ignoring absent/paused reports and retaining256-command work bounds. Native negotiation, calibration, asset loading and remaining resource ownership still require their respective operations; the common helper does not create ASIO timing evidence or physical acceptance.
