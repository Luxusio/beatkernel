# Native runtime boundaries

The user requires native capabilities to be abstracted as far as their actual semantics allow. Gameplay, replay/judgment, multiplayer protocol, screen lifecycle and playback scheduling policy belong in shared runtime code. Operating-system modules provide device ownership/operations, normalized clocks, native acquisition and required cleanup. An OS entry point must not contain an independent multiplayer implementation or repeat the playback-start state machine. Native evidence and limitations remain explicit; abstraction must preserve clock domains, native reading quality, bounded intervals, provenance, callback constraints and failure semantics. Unsupported capabilities are reported rather than replaced with invented observations. No additional crates are required merely to establish these boundaries.

The first migration makes native_start::start_committed the single owner of silent-device startup, bounded calibration, early agreement, session/host bracketing, observed-slope physical-frame projection, exact arming, actual presentation crossing and cancellation/deadline policy. NativeStartDevice exposes only start, bounded acquisition service, normalized observation with original evidence, actual render report/buffer extent and native host sampling. NativeStartAgreement adapts the existing shared LiveCompetition protocol; fake adapters exercise the same owner using an actual gated mixer. ALSA/CoreAudio provide normalized pairs; WASAPI retains its exact accepted snapshot and physical native origin. ASIO requires a bounded-interval adapter before claiming equivalent frame startup.

This migration does not claim all platform code is already thin. Existing gameplay pump, setup/discovery, local-player input dispatch and some completion/recording glue still reside in native entry points. Continue moving shared decisions and sequencing into common components, leaving the unavoidable native calls and resource ownership behind adapters. Preserve bottom-up component construction, one application crate, retained UI and deterministic shared judging/replay. Compiling native adapters is not physical runtime acceptance.

Future presentation coordinates are native capability semantics that the shared owner must handle uniformly. Retain the first qualifying crossing evidence and service acquisition/status/BGM until actual normalized native host time reaches its playback origin. Keep the same deadline and cancellation handling; host-domain/regression errors reject. Do not publish readiness or shift the saved crossing merely because native metadata describes a buffer's future presentation.

Performance remains part of the boundary. Use generic device traits/static dispatch for shared owner paths where practical, reserve startup acquisition storage before use, and keep device waits, clock sampling, locks and allocation out of the audio callback. Abstraction does not imply per-note signals or per-event object allocation. Error boxing on the control owner does not move policy or allocation into real-time rendering.
