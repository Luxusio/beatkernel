# Native runtime boundaries

## Canonical device composition

Production native device implementations use the common GameplayDevice port;
the old NativeGameplayDevice trait remains an external compatibility adapter.
Use canonical gameplay::output domain, application, port and adapter paths in
production imports, retaining the small public legacy re-export modules for
existing clients. Avoid a reverse blanket implementation or another forwarding
trait: those add coherence risk without changing device effects. Generic
composition preserves static dispatch; it does not prove zero overhead in every
device or UI operation. Foreign Rust checks prove types, not native execution.

Dedicated native acquisition follows [the collector contract](REQ__native-input-collector.md).
The source adapter owns native construction, draining and cleanup on one input
thread; shared bounded transport carries original events and ordered genuine
drain cuts. Shared startup/gameplay owners retain admission and domain policy.
They must not infer an acquired prefix from an empty transport queue or their
own later host clock. This migration and independent local QA are complete;
native hardware acceptance remains unproved. Output observation and the
main UI loop retain their existing owners.

The user requires native capabilities to be abstracted as far as their actual semantics allow. Gameplay, replay/judgment, multiplayer protocol, screen lifecycle and playback scheduling policy belong in shared runtime code. Operating-system modules provide device ownership/operations, normalized clocks, native acquisition and required cleanup. An OS entry point must not contain an independent multiplayer implementation or repeat the playback-start state machine. Native evidence and limitations remain explicit; abstraction must preserve clock domains, native reading quality, bounded intervals, provenance, callback constraints and failure semantics. Unsupported capabilities are reported rather than replaced with invented observations. No additional crates are required merely to establish these boundaries.

The first migration makes native_start::start_committed the single owner of silent-device startup, bounded calibration, early agreement, session/host bracketing, observed-slope physical-frame projection, exact arming, actual presentation crossing and cancellation/deadline policy. NativeStartDevice exposes only start, bounded acquisition service, normalized observation with original evidence, actual render report/buffer extent and native host sampling. NativeStartAgreement adapts the existing shared LiveCompetition protocol; fake adapters exercise the same owner using an actual gated mixer. ALSA/CoreAudio provide normalized pairs; WASAPI retains its exact accepted snapshot and physical native origin. ASIO supplies full bounded intervals through the same owner, as described below.

This migration does not claim all platform code is already thin. Solo and local-cohort gameplay now each have a shared owner; some stream/resource glue still resides in native entry points. Common default preparation and recording finalization are described below. Continue moving shared decisions and sequencing into common components, leaving the unavoidable native calls and resource ownership behind adapters. Preserve bottom-up component construction, one application crate, retained UI and deterministic shared judging/replay. Compiling native adapters is not physical runtime acceptance.

Future presentation coordinates are native capability semantics that the shared owner must handle uniformly. Retain the first qualifying crossing evidence and service acquisition/status/BGM until actual normalized native host time reaches the retained host window's upper endpoint. Keep the same deadline and cancellation handling; host-domain/regression errors reject. Do not publish readiness or shift the saved crossing merely because native metadata describes a buffer's future presentation.

Performance remains part of the boundary. Use generic device traits/static dispatch for shared owner paths where practical, reserve startup acquisition storage before use, and keep device waits, clock sampling, locks and allocation out of the audio callback. Abstraction does not imply per-note signals or per-event object allocation. Error boxing on the control owner does not move policy or allocation into real-time rendering.

The second migration places the complete solo gameplay pump in native_gameplay::run_gameplay. NativeGameplayDevice retains only native observation, host sampling, bounded acquisition, end evidence and observation-source reseeding. Shared code owns pause/resume/input admission/watermark/judgment/capture/competition/completion sequencing. The parsed advance lag applies across platforms, and native source identity survives resume. Native setup/discovery remain subsequent migration work; local-cohort loops use the shared owner described below.

The local-cohort migration uses native_cohort::run_cohort over the existing RuntimeGroup and InputMerger. It reuses NativeGameplayDevice, preserving native buffer/end/clock capabilities. Windows solo and cohort sessions use the same Raw Input/output adapter, with a selected attachment slice and original WASAPI snapshot reseeding. Linux adapters retain fair bounded sweeps across evdev owners; macOS retains IOHID health and exact attachment checks. Shared policy owns admission during pending acknowledgements, deterministic merged ordering, one lag frontier, pause-prefix commits, release reconciliation, partial-report capture and actual all-member completion. Per-player configuration, activation and replay saving now use the common composition described below. Chart loading and audio construction use the shared owners described below; publication placement and native cleanup operations remain explicit composition boundaries.

Default preparation now has one owner in native_defaults::prepare for both live play and replay watching. It plans required metadata queries after strict application syntax validation and preserves explicit options. auto_native supplies OS default identity, actual output format, keyboard candidates and explicitly requested ASIO replay format operations. Keyboard selection policy and metadata admission bounds are shared; the adapter preserves native IDs and ordering evidence. The SettingsHost branches describe option-schema/capability differences without duplicating preparation sequencing in OS entry points. Native stream setup remains platform-owned; interval-aware committed startup is shared as described below; local member construction is shared as described below.

Local member composition now belongs to native_cohort_setup: one admitted roster creates exact-device bindings, isolated judges and sound voices, captures, record opponents and full/finite completion metadata. The same owner activates RuntimeGroup and InputMerger from the actual calibrated origin. Native adapters still resolve attachments and negotiate/own streams. After their output stop/join and input close attempts, common finalization matches recording destinations by PlayerId, finishes every opponent and attempts every unambiguous save while preserving session/cleanup/save failures. The create-new capture helper belongs to native_finish and is shared by solo and cohort callers. Chart preparation uses the shared owner below; native calibration evidence and remaining resource composition retain their respective operations. Interval-aware ASIO startup is shared as described below; physical acceptance remains deferred.

Native audio construction now has one owner in native_audio::prepare_audio. It derives the exact bank format, maps section BGM to the declared output/preroll grid, reserves1024 command slots for live work and creates the existing finite/gated mixer. Each native caller supplies its actual rendering bound: ALSA period, CoreAudio buffer or the Windows callback hard bound. Supported solo network modes, including SDK-enabled ASIO, select initial gating; local sessions remain ungated. native_audio::feed_rendered owns checked logical-playback cursor replenishment for both startup and gameplay, ignoring absent/paused reports and retaining256-command work bounds. Native negotiation, calibration evidence and remaining resource ownership still require their respective operations; chart preparation is shared below. The common helper does not create ASIO timing evidence or physical acceptance.

Native chart preparation now belongs to native_chart::prepare_chart. One owner forwards the original path, actual output format, seed, channel policy and PCM limits into the existing loader and section preparer, then checks only retained note lanes for binding coverage. Negative starts reject before file access. Binding failures now precede completion/warning reporting; no other native resource or publication ordering changes. Keep publication separate through the existing player::publish_native_chart owner: Windows solo selects input first, Linux solo builds bindings first, and macOS solo/local publishes before opening input. This preserves attached-only BGA preparation and headless behavior. The helper returns original-song coordinates and section/PCM tail evidence without inventing another clock, player state or native operation. Shared judging/capture preparation is described below. Remaining resource composition stays platform-owned; physical acceptance stays deferred.

Native judging/capture configuration now belongs to native_judge. NativeJudgeConfig prepares the exact grade-one profile and optional full-song completion; capture_limits and prepare_capture retain the existing bounded recording format and pristine-judge checks. JudgeEngine itself was already shared, so no additional constructor wrapper is needed. These operations remain separately callable: solo completion precedes publication, profile creation follows publication/cancellation, and capture remains inside the outcome closure after native owners open. Cohorts prepare one profile, clone it for independent judges, and finish pure member setup before opponent loading. Finite completion and disabled recording skip their unused validation paths. Device selectors, original solo voices, cohort voice partitions, recording paths, competition APIs and native cleanup retain their existing owners. Abstraction does not merge solo and cohort capabilities or change replay bytes. Native resource composition remains platform-owned; shared solo finalization and ASIO interval-aware startup are described below.

Interval startup uses NativeStartTiming to distinguish actual point pairs from bounded host observations. The common owner validates domains and chronology, checks observed calibration against an explicitly assessed rate band, projects the full future band and selects the latest ceiling frame beyond the rendered frontier plus actual buffer. A past average cannot narrow future instantaneous-rate bounds. At the first applied crossing it intersects forward/backward interval projections, preserves original native evidence and waits for actual host time to reach the upper endpoint. NativeStarted keeps the complete window separately from its nominal transport anchor. These bounds remain conditional on the supplied clock/rate assessments.

The Windows adapter retains typed WASAPI snapshots or ASIO observations, caches the buffer size from the actual primed render report and validates the configured sample rate. ASIO seeds finite completion and playback discipline with its original interval/render evidence. Committed ASIO sessions use the existing common logical render scheduler, excluding startup silence from keysound positions; manual ASIO pause remains unsupported. Ordinary ungated ASIO retains its software-frontier fallback. Interval math and real gated-mixer fixtures are prepared for later execution. Ordinary Windows GNU checks do not compile the SDK/MSVC driver branch, and compilation does not establish native or acoustic acceptance.

Solo finalization now has one policy owner in native_finish::finish_solo. Native callers first attempt output stop/join and input close/drop and emit their platform-specific diagnostics. The common owner receives those already evaluated results, finishes optional competition and invokes the capture publisher once even when an earlier stage failed. It then returns the original first error in gameplay/output cleanup/input cleanup/save order. It preserves boxed error identity and the original failed-session flag; it does not aggregate errors or replace resource-retention behavior. Linux input drop has no separate error result. The existing exclusive-create publisher moved unchanged into this module, with native_cohort_setup re-exporting it for compatibility; local cohort all-member finalization remains distinct.
